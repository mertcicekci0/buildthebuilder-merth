The inputs are scattered multimodal business records (2,868 artifacts), an LLM client simulator that holds unwritten facts, a client REST API that may be faulty, an optional inherited codebase, and a serving-model menu with a per-conversation credit budget. The delivered agent is scored on held-out tau-bench-style tasks against a simulated user: S = max(0, mean reward - overage penalty). A task passes when the final DB state matches the annotated outcome and LLM judges accept the rubric-graded communication (sec 3.1 p3-4; sec 3.2 p4-6; App. J-K p39-41). APPROACHES COMPARED (sec 4 p6-7): Codex with GPT-5.6-sol and GPT-5.6-terra; Claude Code with Claude Opus 5 and Claude Sonnet 5; Kimi Code and OpenCode with Kimi K3; and an expert-authored reference ceiling. Each configuration ran one trial per task, offline, with an 8 h build clock. MAIN RESULTS (Table 2 p7): overall pass rate 22.0 / 18.0 / 23.9 / 14.9 / 16.1 / 17.9 %, against an 82.2 % ceiling. Banking scored 3.2-9.0 % against a 79.8 % ceiling, because it carries 2,969 atomic facts (p8). Builds took 47.9-360 min and cost $7-42 at list prices. Agents used 0.38-0.76x of the serving budget, against 0.96x for the reference. Builds asking the client 0 questions averaged 0.16; builds asking 4+ averaged 0.50 (Fig 4 p8). 92 % of the built agents were a single LLM tool loop. A one-line architecture hint ('route by intent, review tool calls') raised a telecom probe from 31 % to 67 % (p9). FAILURE TAXONOMY (sec 6 p9-11, Fig 6 p10): (1) the corpus is searched, not read; (2) the client is rarely interviewed; (3) inherited code is rewritten without being run; (4) quiet API defects are missed; (5) the budget is mismanaged in both directions; (6) developers weaken their own tests. Separately, cheating-adjacent attempts appeared in 17-42 % of runs and none succeeded (p9). FACTORS THAT IMPROVED OUTCOMES: interviewing the client, reporting observed API anomalies to the client (which yielded the idempotency-key plus status-check recovery, p11), the routing and tool-review hint, deterministic policy guards and runtime retrieval (57-71 % of Codex and Claude Code builds, p9), and reading records instead of grepping them. LIMITATIONS (sec 7 p11): a single-LLM client and user, one trial per task with build variance not characterised, planted and consistent facts, and evaluation that ends at submission. RELEVANCE: this is a different benchmark from the hackathon. Its numbers do not predict our score; it is source material, and the official rules (docs/SUBMISSION.md, kit/README.md) govern.
